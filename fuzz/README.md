# Fuzzing

Black-box mutation fuzzer for Kidlat's HTTP/1.1 parser, sent over raw TCP.

## How it works

1. Starts [`lib/server.mjs`](../lib/server.mjs) in a child process.
2. Replays every saved input in [`regressions/`](regressions/).
3. For `FUZZ_MINUTES` (default 120), mutates valid requests (plain, chunked with extensions and trailers, HTTP/1.0) with:
   - bit flips, random byte inserts and deletes
   - framing tokens: `\r\n`, `\n`, `\r`, `:`, `\t`, `\0`, `;`, `chunked`, `Content-Length: `, `Transfer-Encoding: `
   - oversized values (30 digits, 9 KB headers)
   - extra pipelined requests
4. Sends 32 cases at a time from a seeded PRNG, so the same seed always produces the same cases.

## Pass criteria

- The server never crashes.
- Every response starts with `HTTP/1.1 `.
- The server still answers `GET /` with `200` at the end.

## Run

```bash
npm run fuzz
```

| Variable | Default | |
|---|---|---|
| `FUZZ_MINUTES` | `120` | how long to fuzz |
| `FUZZ_SEED` | time-based | PRNG seed (CI uses the run ID) |
| `FUZZ_ITERATIONS` | unlimited | stop after this many cases |

To reproduce a run, use the `seed` and `iterations` from [`results/fuzz.json`](../results/fuzz.json):

```bash
FUZZ_SEED=12345 FUZZ_ITERATIONS=86219 npm run fuzz
```

## Output

- [`results/fuzz.json`](../results/fuzz.json): seed, case count, cases/s, response status counts, and up to 20 failures (base64 input).
- Failing inputs are saved as `regressions/crash-<seed>-<case>.bin` and replayed on every later run. Commit them.

## Limitations

This is not coverage-guided and runs on the published prebuilt binary, so it has no sanitizers. Kidlat's own repo runs libFuzzer with ASan/UBSan on the parser source.
