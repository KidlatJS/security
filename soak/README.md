# Soak

Sustained keep-alive load, looking for errors and memory leaks.

## How it works

1. Starts [`lib/server.mjs`](../lib/server.mjs) in a child process.
2. Opens `SOAK_CONNECTIONS` keep-alive connections and sends requests back to back for `SOAK_SECONDS`. The traffic is a mix of:
   - `GET /` (JSON)
   - `GET /users/123` (route parameter)
   - `GET /missing` (`404`)
   - `POST /echo` with a 1 KB JSON body
3. Reads the server's RSS and heap from `/__mem` every 5 seconds.

## Pass criteria

- Only `200` and `404` responses, with no socket errors.
- The server stays up.
- After a 20% warmup, RSS and heap each grow less than 64 MB.

## Run

```bash
npm run soak
```

| Variable | Default | |
|---|---|---|
| `SOAK_SECONDS` | `3600` | test length (one hour) |
| `SOAK_CONNECTIONS` | `50` | concurrent keep-alive connections |

For a quick check:

```bash
SOAK_SECONDS=30 npm run soak
```

## Output

[`results/soak.json`](../results/soak.json): request count, req/s, error count, RSS and heap growth, peak RSS, status counts, and every memory sample.

## Limitations

In CI the load generator shares a GitHub runner with the server, so throughput is noisy. Compare runs with each other, not with dedicated benchmarks.
